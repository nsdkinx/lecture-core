# Спецификация формата хранения конспектов LectureCore

**Версия:** 1.1  
**Дата:** 18.10.2025

Этот документ описывает файловую структуру и формат данных для организации и хранения моих учебных конспектов. Система спроектирована с упором на **простоту**, **долговечность**, **кросс-платформенность** и **машиночитаемость**.

-----

## 1\. Структура директорий

Система имеет иерархическую структуру, в корне которой находится конфигурационный файл и папки для каждого учебного предмета.

### 1.1. Корневой уровень

В корневой директории находятся:

1.  **`subjects.json`**: Файл-словарь, сопоставляющий короткие, удобные для использования **ID предметов** с их полными, официальными названиями.
2.  **Папки предметов**: Для каждого предмета создается отдельная папка.

### 1.2. Файл `subjects.json`

Это обязательный JSON-файл, который служит центральным реестром всех учебных дисциплин.

  * **Формат**: JSON-объект (словарь).
  * **Ключ**: Строка. Уникальный, короткий идентификатор предмета в нижнем регистре (например, `"обп"`, `"философия"`). Используется в метаданных и скриптах.
  * **Значение**: Строка. Полное, человекочитаемое название предмета (например, `"Основы бережливого производства"`). Это название используется для создания папки предмета.

**Пример `subjects.json`:**

```json
{
    "философия": "Основы философии",
    "обп": "Основы бережливого производства",
    "фин_грамотность": "Основы финансовой грамотности"
}
```

### 1.3. Папка предмета

Название папки для каждого предмета **точно соответствует** значению из файла `subjects.json`.

`./Основы философии/`
`./Основы бережливого производства/`

### 1.4. Папка занятия

Каждое отдельное занятие (лекция или практика) хранится в своей собственной папке внутри папки соответствующего предмета. Это позволяет сгруппировать конспект и все связанные с ним материалы.

**Шаблон именования папки:** `ГГГГ-ММ-ДД.тип-ID.Очищенное_название_темы`

  * **`ГГГГ-ММ-ДД`**: Дата занятия в формате ISO 8601. Гарантирует хронологическую сортировку.
  * **`тип`**: Тип занятия. Может быть `л` (лекция) или `пр` (практика).
  * **`ID`**: Порядковый номер занятия *в рамках данного предмета*.
  * **`Очищенное_название_темы`**: Название темы занятия, из которого удалены все недопустимые для имен файлов символы, а пробелы и точки заменены на подчёркивания.

**Пример имени папки:** `2025-09-01.пр-1.Понятие_философии_её_смысл_и_предназначение`

-----

## 2\. Структура файлов внутри папки занятия

Внутри каждой папки занятия находится как минимум один файл — сам конспект в формате Markdown.

### 2.1. Файл конспекта

  * **Расширение**: `.md`
  * **Имя файла**: Имя файла конспекта **полностью совпадает** с именем родительской папки.

**Пример:**
Для папки `2025-09-01.пр-1.Понятие_философии_её_смысл_и_предназначение/` файл конспекта будет называться `2025-09-01.пр-1.Понятие_философии_её_смысл_и_предназначение.md`.

### 2.2. Формат файла конспекта

Файл состоит из двух частей:

1.  **YAML Front Matter**: Блок с метаданными в начале файла.
2.  **Содержимое конспекта**: Текст в формате Markdown.

#### 2.2.1. Метаданные (YAML Front Matter)

Блок начинается и заканчивается тремя дефисами (`---`). Он содержит ключевые атрибуты занятия в формате `ключ: значение`.

| Ключ | Тип данных | Обязательность | Описание |
| :--- | :--- | :--- | :--- |
| `subject_name` | str | Да | Полное название предмета. Должно совпадать со значением в `subjects.json`. |
| `subject_id` | str | Да | Короткий ID предмета. Должен совпадать с ключом в `subjects.json`. |
| `date` | str | Да | Дата занятия в формате `YYYY-MM-DD`. |
| `type` | str | Да | Тип занятия. Допустимые значения: `'л'` или `'пр'`. |
| `class_id` | int | Да | Порядковый номер занятия по всему предмету. |
| `absolute_lecture_id` | int | Да | Номер занятия по официальному расписанию звонков на день. |
| `relative_lecture_id` | int | Да | Фактический порядковый номер занятия в этот учебный день (например, если занятия начались со 2-й пары по расписанию, её `relative_lecture_id` будет `1`). |
| `classroom` | str | Да | Номер аудитории или место проведения. |

#### 2.2.2. Содержимое конспекта (Markdown)

Сразу после закрывающего `---` блока метаданных следует текст конспекта.

  * **Формат**: CommonMark или GitHub Flavored Markdown (GFM).
  * **Рекомендация**: Начинать конспект с заголовка первого уровня (`#`), дублирующего тему занятия для лучшей читаемости.

### 2.3. Вложения

Любые дополнительные файлы, относящиеся к занятию (презентации, изображения, документы, архивы), размещаются в той же папке, что и `.md` файл конспекта.

## 3\. Итоговый пример

Ниже представлен полный пример одного занятия по философии.

**Содержимое `subjects.json`:**

```json
{
    "философия": "Основы философии",
    ...
}
```

**Структура папок и файлов:**

```
.
├── Основы философии/
│   └── 2025-09-01.пр-1.Понятие_философии_её_смысл_и_предназначение/
│       ├── 2025-09-01.пр-1.Понятие_философии_её_смысл_и_предназначение.md
│       └── Философия_ПЗ_1.docx
└── subjects.json
```

**Содержимое файла `2025-09-01.пр-1.Понятие_философии_её_смысл_и_предназначение.md`:**

```markdown
---
subject_name: 'Основы философии'
subject_id: 'философия'
date: 2025-09-01
type: 'пр'
class_id: 1
absolute_lecture_id: 2
relative_lecture_id: 1
classroom: '404'
---

# Понятие философии, её смысл и предназначение

## 1. Основные определения

**Философия** (от др.-греч. φιλέω — люблю, σοφία — мудрость) — особая форма познания мира, вырабатывающая систему знаний о наиболее общих характеристиках и фундаментальных принципах реальности (бытия) и познания, бытия человека, об отношении человека и мира.
```
