# Взаимодействие с конспектами через LectureRepository

**Версия:** 1.0  
**Дата:** 18.10.2025

Этот документ предоставляет детальное описание API для взаимодействия с хранилищем конспектов LectureCore. Центральным компонентом API является класс `LectureRepository`, который абстрагирует все операции с файловой системой и предоставляет методы для управления учебными материалами.

Для использования API необходимо импортировать соответствующие классы из модуля `lecture_repository.py`.

```python
from lecture_repository import LectureRepository, LectureType
```

-----

## 1\. Основные классы

Система API построена вокруг двух ключевых классов:

  * **`LectureRepository`**: Основной класс, служащий точкой входа для работы с хранилищем. Он управляет загрузкой, поиском, созданием и сохранением конспектов.
  * **`Lecture`**: Класс-модель, представляющий один конспект (лекцию или практику). Он содержит все метаданные (из YAML Front Matter) и текстовое содержимое. Объекты этого класса не создаются напрямую, а получаются через методы `LectureRepository`.

-----

## 2\. Инициализация `LectureRepository`

Для начала работы необходимо создать экземпляр класса `LectureRepository`, передав в конструктор путь к корневой директории вашего хранилища конспектов.

```python
repo_path = Path('.') # Укажите путь к вашей папке с конспектами
repo = LectureRepository(repo_path)
```

При инициализации `LectureRepository` выполняет следующие действия:

1.  Проверяет наличие файла `subjects.json` в указанной директории.
2.  Загружает и кэширует содержимое `subjects.json` для сопоставления ID предметов с их полными названиями.

> **Важно:** Если файл `subjects.json` не будет найден, класс вызовет исключение `FileNotFoundError`.

-----

## 3\. Публичный API `LectureRepository`

Класс предоставляет три основных метода для взаимодействия с хранилищем.

### 3.1. `get_all_lectures()`

Сканирует все папки предметов в хранилище и возвращает полный список всех найденных конспектов.

  * **Сигнатура:** `get_all_lectures() -> List[Lecture]`
  * **Возвращает:** Список (`List`) объектов `Lecture`. Если конспекты не найдены, возвращает пустой список.
  * **Описание:** Метод рекурсивно обходит директории, соответствующие предметам из `subjects.json`, находит все файлы `.md` и десериализует каждый из них в объект `Lecture`. Если при чтении какого-либо файла возникает ошибка (например, из-за некорректного формата), в консоль выводится сообщение об ошибке, а сам файл пропускается.

**Пример использования:**

```python
all_lectures = repo.get_all_lectures()
print(f"Всего конспектов в хранилище: {len(all_lectures)}")
for lecture in all_lectures:
    # lecture.uid — это уникальный идентификатор вида "философия-пр-1"
    # lecture.topic — это название темы
    print(f" - {lecture.uid}: {lecture.topic}")
```

### 3.2. `get_lecture_by_uid()`

Осуществляет быстрый поиск одного конспекта по его уникальному идентификатору (`uid`).

  * **Сигнатура:** `get_lecture_by_uid(uid: str) -> Optional[Lecture]`
  * **Параметры:**
      * `uid` (str): Уникальный идентификатор конспекта. Формируется по шаблону `{subject_id}-{type}-{class_id}` (например, `"философия-пр-1"`).
  * **Возвращает:** Объект `Lecture`, если конспект с таким `uid` найден, в противном случае — `None`.

**Пример использования:**

```python
my_lecture = repo.get_lecture_by_uid('философия-пр-1')

if my_lecture:
    print(f"Найдена лекция: {my_lecture.topic}")
    print(f"Содержимое: \n{my_lecture.content[:50]}...")
else:
    print("Лекция с таким UID не найдена.")
```

### 3.3. `create_new_lecture()`

Создает в памяти новый объект `Lecture`, готовый для наполнения и последующего сохранения.

  * **Сигнатура:** `create_new_lecture(subject_id: str, lecture_type: LectureType, topic: str, classroom: str, date: Optional[datetime.date] = None, absolute_lecture_id: int = 1, relative_lecture_id: int = 1) -> Lecture`
  * **Основные параметры:**
      * `subject_id` (str): Короткий ID предмета (обязательно должен существовать как ключ в `subjects.json`).
      * `lecture_type` (LectureType): Тип занятия. Используйте `LectureType.LECTURE` для лекции или `LectureType.PRACTICE` для практики.
      * `topic` (str): Название темы занятия.
      * `classroom` (str): Номер аудитории или место проведения.
      * `date` (Optional[date]): Дата занятия. Если не указана, используется текущая дата.
  * **Возвращает:** Новый объект `Lecture` с автоматически вычисленным `class_id` (на единицу больше максимального существующего `id` для данного предмета и типа занятия).

> **Внимание\!** Этот метод **не сохраняет** файл на диск. Он только подготавливает объект в памяти. Для физического создания файла необходимо вызвать метод `.save()` у возвращенного объекта `Lecture`.

**Пример использования:**

```python
from lecture_repository import LectureType
import datetime

# Создаем объект лекции в памяти
new_lecture = repo.create_new_lecture(
    subject_id='обп',
    lecture_type=LectureType.LECTURE,
    topic="Принципы Кайдзен и система 5S",
    classroom="301b",
    date=datetime.date(2025, 10, 20)
)

print(f"Подготовлен новый конспект: {new_lecture.uid}")
# На этом этапе файла на диске еще нет.
```

## 4\. Работа с объектом `Lecture`

Объекты `Lecture`, полученные из `LectureRepository`, предоставляют полный доступ к данным конспекта.

### 4.1. Атрибуты

#### Атрибуты для чтения и записи:

  * `topic` (str): Тема занятия.
  * `content` (str): Полное текстовое содержимое конспекта в формате Markdown (все, что идет после YAML-блока).
  * `classroom` (str): Аудитория.
  * `date` (datetime.date): Дата занятия.
  * `subject_name` (str): Полное название предмета.
  * `subject_id` (str): ID предмета.
  * `type` (LectureType): Тип занятия.
  * `class_id` (int): Порядковый номер занятия.
  * `absolute_lecture_id` (int): Номер по официальному расписанию.
  * `relative_lecture_id` (int): Фактический номер в учебный день.

#### Атрибуты только для чтения:

  * `uid` (str): Уникальный идентификатор (`философия-пр-1`).
  * `path` (Path): Абсолютный путь к файлу конспекта на диске.

### 4.2. Метод `save()`

Сохраняет текущее состояние объекта `Lecture` в файл на диске. Это ключевой метод для создания новых конспектов и применения изменений к существующим.

  * **Сигнатура:** `save()`
  * **Действие:**
    1.  Формирует YAML Front Matter на основе текущих атрибутов объекта.
    2.  Объединяет метаданные и содержимое (`content`) в единый текст.
    3.  Вычисляет корректное имя файла и папки на основе `date`, `type`, `class_id` и `topic`.
    4.  **Автоматическое переименование:** Если вы изменили атрибут, влияющий на имя файла (например, `topic` или `date`), метод `save()` автоматически переименует не только `.md`-файл, но и родительскую папку, а также переместит в нее все вложенные файлы (изображения, презентации и т.д.).
    5.  Записывает полное содержимое в файл, при необходимости создавая новую структуру папок.

**Пример сохранения нового конспекта:**

```python
# (Продолжение примера с create_new_lecture)
new_lecture.content = "# Ключевые принципы\n\n1. Сортируй\n2. Соблюдай порядок\n..."
new_lecture.save() # В этот момент на диске будет создана папка и .md файл
print(f"Конспект '{new_lecture.uid}' успешно сохранен по пути: {new_lecture.path}")
```

**Пример модификации существующего конспекта:**

```python
lecture_to_edit = repo.get_lecture_by_uid('философия-пр-1')
if lecture_to_edit:
    print(f"Старая тема: {lecture_to_edit.topic}")
    
    # Изменяем атрибуты
    lecture_to_edit.topic = "Введение в античную философию"
    lecture_to_edit.classroom = "222"
    lecture_to_edit.content += "\n\n**UPD:** Добавлена информация о Сократе."
    
    # Сохраняем изменения. Файл и папка будут автоматически переименованы.
    lecture_to_edit.save() 
    print(f"Новая тема: {lecture_to_edit.topic}")
```
